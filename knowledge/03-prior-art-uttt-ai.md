# 03 - Prior art: AI for Ultimate Tic-Tac-Toe (UTTT)

Compiled 2026-08-29. Scope: everything findable on UTTT AI - AlphaZero-style agents, CodinGame's arena, solvers, RL frameworks, and published strategy analysis - and a judgment on whether an AlphaZero-style agent for the **closed-board + most-won-boards** (CodinGame) variant, trained on a home PC and used for strategy analysis, has already been done.

## 0. The rule variants (read this first)

"Ultimate Tic-Tac-Toe" hides at least three games. Almost every prior project used a different one from the user's, and strength claims do not transfer across variants.

| Variant | Won/full local boards | Sent to a closed board | No macro line at the end | Solved? |
|---|---|---|---|---|
| **Open-board** (original Math with Bad Drawings rules) | still playable | must play there anyway | draw | **Yes** - X wins in <= 43 moves ([Bertholon et al. 2020, arXiv:2006.02353](https://arxiv.org/abs/2006.02353)) |
| **Closed-board / draw** (Wikipedia, uttt.ai, OpenSpiel, nelhage) | closed | play anywhere | draw | No |
| **Closed-board / most boards** (CodinGame) | closed | play anywhere | player with more won local boards wins | No |

The CodinGame rule is confirmed in the referee source: each won local board adds 1 to the player's score, a macro line sets the score to 10, and the higher score wins at game end ([Referee.java](https://github.com/CodinGame/game-ultimate-tictactoe/blob/master/src/main/java/com/codingame/game/Referee.java)); forum regulars state it plainly ("if no player has 3-in-row in main board, the player with more miniboards won wins" - jacek, [CG forum, Feb 2022](https://forum.codingame.com/t/ultimate-tic-tac-toe-puzzle-discussion/22616?page=7)). The referee also sets 1000 ms for the first turn and 100 ms afterwards, and caps the game at 81 turns.

The tiebreak matters more than it looks. Under the draw variant, strong engines draw a lot: SaltZero's 200-game match against the then-#2 CodinGame bot scored +65 =96 -39, i.e. 48% draws ([SaltZero README](https://github.com/farmersrice/saltzero)). Under CodinGame rules those games would all have had a winner, and "trade a local board to gain tempo" has a different price. Any agent or analysis built for the draw variant is only approximately right for the user's game.

## 1. AlphaZero-style and neural-network projects

### 1.1 uttt.ai (Arkadiusz Nowaczynski, 2021) - the strongest public system

- Repo: [ar-nowaczynski/utttai](https://github.com/ar-nowaczynski/utttai) (Apache-2.0; JS + Python + C++). Site: [uttt.ai](https://uttt.ai) with a **playable browser demo and an Analysis mode** (onnxruntime WebAssembly SIMD, ~75 sims/s on a desktop). Write-up: [uttt.ai/blog](https://uttt.ai/blog); [HN thread](https://news.ycombinator.com/item?id=29594786).
- Rules: closed-board / **draw** variant ([uttt.ai/rules](https://uttt.ai/rules) shows DRAW as an outcome; no most-boards tiebreak).
- Network: ~5 M params (20 MB). A custom, non-standard architecture: a 3x3-stride conv collapses each local board to one cell, 1x1 and depthwise-3x3 residual blocks operate on the 3x3 macro grid, and a ConvTranspose2d upsamples back to 9x9 for the policy; separate value head; auxiliary action-value head ([policy_value_network.py](https://github.com/ar-nowaczynski/utttai/blob/main/utttpy/selfplay/policy_value_network.py)). Input is 4 planes.
- Training: **offline, two-stage**, not a live AlphaZero loop. Stage 1: 8.0 M positions labelled by pure MCTS with random playouts (average 1.36 M simulations per position); stage 2: 8.0 M positions labelled by neural MCTS at 10 k sims each ([datasets/README](https://github.com/ar-nowaczynski/uttt/blob/main/datasets/README.md)). Value target is the root's mean MCTS value, not the game result; policy loss is masked KL. Hardware: i7-10700K, 2x RTX 2080 Ti, 64 GB; **about 10 weeks** wall-clock, mostly C++ self-play. Datasets and checkpoints are downloadable (Google Drive link in README), and a refactored copy sits on Hugging Face ([markstanl/u3t](https://huggingface.co/datasets/markstanl/u3t)).
- Strength: evaluated only against its own baselines - "NMCTS2 beats MCTS baseline even with 4 orders of magnitude difference in the number of simulations (1k vs 10M)" - and against consumer apps ("uttt.ai beats them all"). No match against CodinGame Legend bots or SaltZero was published. The author notes the raw network mis-evaluates some positions and needs >= 1000 sims for reliable evaluations.
- Strategy analysis: yes, a short prose list "learned from AI" (see section 6). No heatmaps, opening book or first-move value table.

### 1.2 SaltZero (Anson Hu, 2019-2020) - the only NN bot benchmarked against a top CodinGame bot

- Repo: [farmersrice/saltzero](https://github.com/farmersrice/saltzero) (GPL-3.0; C++ engine + TensorFlow/Python NN, batched self-play of 1000 games at once). Weights released in [releases](https://github.com/farmersrice/saltzero/releases) (v0.0.4, Dec 2020; a third party notes the model is >200 MB). Pinned to an old TF; the author's Jan 2026 note recommends Python 3.11.9 + tensorflow 2.12.
- Rules: Wikipedia closed-board / draw variant. The README explicitly rejects the "UTTT is solved" claim as applying only to the open-board variant.
- Network: **dense, no convolutions** (author's argument: adjacent cells across local-board borders are unrelated) - 7 residual blocks of two 1024-unit dense layers; 200 visits/move in self-play; ~10 k games/hour on a Ryzen 7 3700X + RTX 2070 Super; 52.5% gating over 400 games; Dirichlet alpha 0.3.
- Strength: "Stronger than the second highest ranked bot on codingame" - 113-87 (+65 =96 -39) over 200 games at 400 ms/move against NinjaDoggy's Legend bot, whose source was provided privately. Claimed "potentially superhuman". Ships `arbiter.cpp` / `bot.cpp` so third parties can pit their bot against it via a simple stdin/stdout protocol ([cpp_impl README](https://github.com/farmersrice/saltzero/blob/master/cpp_impl/README.md)).
- Strategy analysis: informal - the net "understands ... that the optimal move might not be the one that wins the local board" and traps opponents in positions where "almost any move will send the bot to a won square" (the tempo / free-move concept).

### 1.3 reCurse's "Totozero" and other NN bots inside CodinGame (2021-)

reCurse, a top CodinGame competitor, built an AlphaGo-Zero-style RL pipeline over Christmas 2020 motivated by "accumulated years of frustration / hatred at being unable to gain a significant edge with my bot at Ultimate-Tic-Tac-Toe", and with it "briefly took the #1 spot" in the UTTT arena ([Spring Challenge 2021 post-mortem](https://forum.codingame.com/t/spring-challenge-2021-feedbacks-strategies/190849/67)). Another Legend player confirms "reCurse uses mcts with CNN for his bot", and describes his own bot as "mcts 'ept' with one-hots NN (very similar to NNUE)" ([jacek, CG forum Feb 2022](https://forum.codingame.com/t/ultimate-tic-tac-toe-puzzle-discussion/22616?page=7)). These are, by construction, the only AlphaZero-style agents trained on the **exact CodinGame rules** that I can find - and none of their code, weights or analysis is public. They must fit in 100 KB of source and run single-threaded in 100 ms, so they are tiny nets bolted onto fast bitboard MCTS.

## 2. Academic work

- **Addison, Peeler, Alvin (Furman Univ.), "Ultimate Tic-Tac-Toe Bot Techniques", FLAIRS-35, 2022** ([abstract](https://journals.flvc.org/FLAIRS/article/view/130698), [PDF](https://journals.flvc.org/FLAIRS/article/download/130698/133960)). Random vs heat-map vs MCTS (0.1 s and 1 s) vs "AlphaZero-inspired" CNN trained for 24 hours on MCTS-generated data; 10 000 games per pairing. The AZ bot won 88% of its 50 000 games; their MCTS at 0.1-1 s "cannot reach a depth that vastly outperforms random moves" and the hand-made heat-map beat it - which says more about their MCTS than about UTTT. Two-page abstract; no weights.
- **D'Alberton, "A Reinforcement Learning Journey in Ultimate Tic Tac Toe", MSc Computer Engineering, Univ. of Padua, 2024/25** ([thesis](https://thesis.unipd.it/handle/20.500.12608/86899)). DQN, DDQN, A2C, PPO via self-play; Elo and round-robins; adds **best-response training** to measure exploitability and finds "significant vulnerabilities in self-play agents". Final residual DDQN wins 85% vs the other trained agents. No MCTS/AlphaZero, no external baseline.
- **Sista, "Adversarial Game Playing Using Monte Carlo Tree Search", MSc, Univ. of Cincinnati, 2016** ([OhioLINK PDF](https://etd.ohiolink.edu/acprod/odb_etd/ws/send_file/send?accession=ucin1479820656701076&disposition=inline)). MCTS vs minimax on UTTT under time limits; MCTS wins.
- **Bichot et al., "Reinforcement Learning Project: Ultimate Tic-Tac-Toe", Ecole Polytechnique INF581, 2022** ([PDF](https://josselinsomervilleroberts.github.io/papers/Report_INF581.pdf)). Minimax / MCTS / DQN; DQN after 15 000 games could not beat random; depth-6 minimax with a tuned reward was their best.
- **Chen, Doan, Xu, "AI Agents for Ultimate Tic-Tac-Toe", 2018** - cited as [CDX18] by Bertholon et al.; a Stanford course report I could not locate online.
- **Macchiavello Cauvi & Alqassab, Columbia COMS 4995, 2023** ([PDF](https://www.cs.columbia.edu/~sedwards/classes/2023/4995-fall/reports/UTTSolver-report.pdf)) - parallel Haskell alpha-beta, depth 6; engineering report.

Nothing peer-reviewed trains a serious AlphaZero agent for UTTT, and nothing academic touches the most-boards variant.

## 3. The CodinGame arena

- Size: ~10 050 CodinGamers in the arena; **Legend league ~407-423 bots**, Gold ~1380, Silver ~1200, Bronze ~5660 *(refreshed 2026-09-12 from the leaderboard API: 10 085 entrants; Legend 431 / Gold 1 388 / Silver 1 202 / Bronze 5 671 / Wood 1 397; reCurse 7th, jacek 11th — knowledge/07 §2.3)* ([leaderboard](https://www.codingame.com/multiplayer/bot-programming/tic-tac-toe/leaderboard)). Languages skew C++ (1900) / Python (3800, almost none in Legend).
- Constraints: 100 ms/turn (1000 ms on turn 1), single core, 100 KB source; NN weights must be embedded in the source as encoded strings ([forum guidance](https://forum.codingame.com/t/winter-challenge-2024-feedback-and-strategies/205711/87)).
- What Legend bots do: bitboard MCTS with random playouts, an MCTS **solver** (proven-win backprop, citing Winands' "MCTS Solver" and "Score Bounded MCTS" - [darkhorse64](https://forum.codingame.com/t/ultimate-tic-tac-toe-puzzle-discussion/22616?page=6)), tree reuse, low exploration constants, 1-ply win checks in playouts, node pools of millions. Throughput quoted by players: ~20-25 k rollouts/turn gets you into Legend; "optimize further your bot to reach 80-90k and add a solver to make it into top 50" (darkhorse64, [page 8](https://forum.codingame.com/t/ultimate-tic-tac-toe-puzzle-discussion/22616?page=8)); a plain flat-MC bitboard example does "500,000 simulations within 99 milliseconds"; Magus allocates 5 M nodes on turn 1.
- NN bots: reCurse (CNN + MCTS, briefly #1) and jacek (NNUE-like one-hot net + MCTS-EPT) as above; pb4 and Agade pioneered NN/RL bots on CG in 2019 for other games. None published for UTTT.
- First-player advantage: "P1 has a 60% winrate for UTTT so chances are not equal" (darkhorse64, Aug 2020, [page 5](https://forum.codingame.com/t/ultimate-tic-tac-toe-puzzle-discussion/22616?page=5)); players agree "either p1 wins or a draw can be forced" and that P2 winning under optimal play is "highly improbable" (sscg13 / jacek, page 7). These are impressions from the Legend arena, not measured statistics from a fixed pair of bots.
- Opening books: several bots hardcode the first move (centre board, some square) and small precomputed books; one Gold-league write-up found caching first moves "didn't seem to matter too much" ([hodina.net](https://dev.hodina.net/how-to-create-a-gold-league-bot-on-codingame)). A theaigames-era bot ran mass Monte Carlo and put the centre opening at "about 52% chance of winning" ([royerk](https://royerk.github.io/Neural-Network-UT3/)). No Legend bot has published an opening analysis.
- Tooling: official referee [CodinGame/game-ultimate-tictactoe](https://github.com/CodinGame/game-ultimate-tictactoe) (Java, SDK) usable with [cg-brutaltester](https://github.com/dreignier/cg-brutaltester); [Agade09/CG-UTTT-Arena](https://github.com/Agade09/CG-UTTT-Arena) (C++, Linux, plays two stdin/stdout bots; its README still carries Wondev Woman boilerplate); link hub at [yduf's page](https://yduf.github.io/CG-tic-tac-toe). Public Legend-level bot sources are rare; many Gold/Silver MCTS bots are on GitHub (e.g. [Uriopass/MCTSUTTT](https://github.com/Uriopass/MCTSUTTT), [EllainYang/UTTT_bot](https://github.com/EllainYang/UTTT_bot), [sys27/UltimateTicTacToe](https://github.com/sys27/UltimateTicTacToe)).

## 4. Non-NN engines and solving attempts

- **Nelson Elhage, [ultimattt](https://github.com/nelhage/ultimattt) (Rust, Apache-2.0), write-up at [minimax.dev](https://www.minimax.dev/docs/ultimate/) (2020).** Closed-board / draw variant ([rules page](https://minimax.dev/docs/ultimate/the-game/)). Bitboards with SIMD win checks, Zobrist hashing, minimax AI, plus PN / DFPN / a parallel hybrid PN-DFPN solver with a lock-free transposition table and "critical square" positional pruning ([pruning page](https://www.minimax.dev/docs/ultimate/pruning/)). Status: solves positions "after about 20 ply ... in a few hours" on a Ryzen 3900X; estimates the full game at "a few hundred million CPU-hours", roughly $2-10 M of cloud time. No endgame database ("I currently do not see a clear way to build endgame databases"). No first-move values published. PN search treats draw as not-win, so even a finished run would only say whether X forces a win.
- **Bertholon, Geraud-Stewart, Kugelmann, Lenoir, Naccache (ENS Paris), 2020** ([arXiv:2006.02353](https://arxiv.org/abs/2006.02353)): open-board variant only - X has a forced win in at most 43 moves, O can hold out 29, and the first two moves of any optimal strategy are identified. Implication for prior art: **nothing** for the closed-board game; it establishes that the closed-board rule is what keeps UTTT interesting, and Wikipedia records the closed-board game as unsolved.
- Alpha-beta bots ([lorenzofavaro](https://github.com/lorenzofavaro/ultimate-tic-tac-toe), [Zslez](https://github.com/Zslez/Ultimate-Tic-Tac-Toe), [zesardine](https://github.com/zesardine/UltimateTicTacToeAI) with the "unstoppable" [YouTube video](https://www.youtube.com/watch?v=BfmivoVFins), [xpe/rs-uttt](https://github.com/xpe/rs-uttt)) top out around CodinGame Silver; the game lacks a good static evaluation, which is exactly the gap a value net fills.
- No endgame tablebase, retrograde analysis, or solved-opening claim exists for the closed-board variants in either tiebreak.

## 5. Frameworks and environments

- **OpenSpiel** has `ultimate_tic_tac_toe` ([source](https://github.com/google-deepmind/open_spiel/blob/master/open_spiel/games/ultimate_tic_tac_toe/ultimate_tic_tac_toe.cc), Apache-2.0). Rules: closed boards; draw when all nine local boards are terminal; **no most-boards tiebreak**. Implementation quirks that matter for training: when sent to a closed board the player makes a separate "choose local board" action first (so a free move is two plies and the action space is 9, not 81), and `UndoAction` is a no-op. Observation tensor is 3x9x9 + current player + a 10-way forced-board one-hot. The generic `alpha_zero` example works on any registered game but DeepMind published **no UTTT AlphaZero results** ([alpha_zero docs](https://openspiel.readthedocs.io/en/latest/alpha_zero.html)).
- **Pgx** (JAX): no UTTT in its game list ([pgx README](https://github.com/sotetsuk/pgx)).
- **Ludii** includes an Ultimate Tic-Tac-Toe ruleset ([ludii.games](https://ludii.games/details.php?keyword=Ultimate+Tic-Tac-Toe)) and the Ludii-Polygames bridge can train AZ-style models on any Ludii game ([Soemers et al. 2022](https://doi.org/10.3233/icg-220197)); no UTTT results were reported.
- **LightZero**, **muzero-general**: tic-tac-toe only; UTTT exists only as the unreported fork above.
- **Datasets:** uttt.ai's 16 M MCTS-labelled positions (Drive link in its README; [Hugging Face mirror](https://huggingface.co/datasets/markstanl/u3t)). Draw-variant labels, but the game tree is identical to CodinGame's until the final position, so they remain useful for supervised warm-starting.

## 6. Published strategy analysis derived from AI

What exists is thin and prose-only:

- **uttt.ai's "strategy learned from AI"** ([blog](https://uttt.ai/blog)): open in the centre square of the centre board ("undoubtedly the best move"); O's best reply pushes play into a corner board, and the next ~8 moves stay in the corner boards; when play breaks out, "jump between the side subgames (these are the least useful to take)"; keep the position balanced and wait for a mistake; and "think twice before sending your opponent to the finished subgame (being able to choose any move from the unfinished subgames is very powerful)". Also a worked example where the network's greedy choice (win the centre board) loses and only >300 sims find the drawing move. Self-play statistics: 40-50 plies per game, ~7 legal moves per position.
- **SaltZero**: the net learns not to win local boards when that is bad, and to trap opponents so that every move gives the bot a free move.
- **nelhage's critical-square analysis**: when one player is one move from a macro win in some board, the opponent must never play into the corresponding relative square anywhere, and boards whose only open squares are such squares become forced losses - a rigorous statement of the tempo concept, used for pruning ([pruning page](https://www.minimax.dev/docs/ultimate/pruning/)).
- **Monte Carlo opening statistics** (royerk): centre opening ~52% for X under random-playout MC; a best-reply matrix, unpublished.
- **CodinGame folk knowledge**: P1 ~60% among Legend bots; game length 50-60 moves; local-board sacrifices are common.
- Human guides ([tictoe.org](https://tictoe.org/games/ultimate-tic-tac-toe), [tictactoefun](https://tictactoefun.com/blog/ultimate-strategy.html)) repeat centre-centre as best and warn about free moves, without evidence.

**Not found anywhere:** an 81-cell first-move value heatmap from a strong agent, a reply table for X's opening, a quantified value of a free move, draw/win rates by opening under either tiebreak, or any of this for the most-boards variant.

## JUDGMENT

**(a) Has anyone trained a strong AlphaZero-style agent for the closed-board + most-won-boards variant? Score: 2/10 for the exact variant, 7/10 for the closed-board family.**
Two people have almost certainly done it - reCurse (briefly #1 on CodinGame) and jacek (Legend) - but under CodinGame's 100 KB / 100 ms constraints and entirely in private. Every public agent uses the draw tiebreak: uttt.ai (10 GPU-weeks, offline two-stage, clearly strong but never benchmarked against Legend bots) and SaltZero (dense net, beat the #2 CodinGame bot 113-87 at 400 ms/move in 2020). Neither trained on the most-boards rule, and SaltZero's 48% draw rate shows that rule is not a footnote. The home-PC feasibility question is answered, though: uttt.ai on one i7 + two 2080 Ti, and reCurse's Spring-2021 bot on an i7-8700K + RTX 3080 in ~50 hours, both reached the top of their respective ladders.

*Addendum 2026-09-12 (knowledge/07 §2.2; verified against the GitHub API and the README):* **(a) is superseded.** [pc29277/AlphaZero_UTTT](https://github.com/pc29277/AlphaZero_UTTT), created 2026-08-19 — ten days before this note — is a public AlphaZero on the exact closed-board / most-boards rules ("if the board you are sent to is closed … you can play anywhere … If there is a draw, whoever has more local boards wins"): 10 × 128, 2 983 770 parameters, PUCT at 100 sims, 8× D4 augmentation, 28 544 self-play games in 22 T4-hours, 76.0 % [score 0.780 ± 0.079] against a depth-3 alpha-beta in 100 paired games, no license, no analysis of the game, and a README that says its own in-run Elo was meaningless. The novelty claim moves from "first public AlphaZero on this variant" to "first with a calibrated external strength measurement, a replicated recipe ladder, and the agent used to produce game knowledge" — its strongest opponent is roughly CodinGame Silver, against which `v2b` (≈ +169 over a 100 k-playout rollout UCT) is already far ahead.

**(b) Released in a usable form? Score: 6/10.**
uttt.ai: full source (Apache-2.0), weights, datasets, browser demo with analysis mode, ~700 sims/s in C++. SaltZero: source (GPL-3), weights, a stdin/stdout arbiter for bot-vs-bot matches, on a bit-rotted TF stack. tacult: MIT, C++ engine, vectorized MCTS, demo. Everything else is unusable as a baseline (no weights, no strength data, or both). The CodinGame NN bots are not released at all.

**(c) Used to analyze strategy? Score: 2/10.**
A five-bullet prose list on uttt.ai and scattered forum remarks. No heatmaps, opening trees, tempo valuation, or first-player-advantage measurement from a strong agent exists for any variant, let alone the user's.

**What remains novel or valuable in the user's project:**
1. First public AlphaZero-style agent trained on the CodinGame rules, with a calibrated strength measurement against SaltZero and a Legend-level MCTS bot through the CodinGame referee / brutaltester.
2. Any quantitative strategy output at all: first-move value map, X's opening book and O's replies, value of a free move, how often the most-boards tiebreak decides games at high level, P1 win rate under strong play - none of it exists.
3. A comparison of the two tiebreaks using the same agent (how much strategy changes when draws become most-boards wins) would be new.
4. Methodological: a modern, GPU-batched, honest-Elo pipeline for a game where every prior public attempt either had no benchmark or ran offline for ten weeks.

**Best starting points / baselines:**
- **Strongest available test opponent: SaltZero** ([farmersrice/saltzero](https://github.com/farmersrice/saltzero), GPL-3). It is the only released NN agent with an external, top-CodinGame-bot benchmark, and it ships an arbiter and a line protocol (opponent's last move in; row col out). Cost: pinning Python 3.11 + TF 2.12, and its draw-variant semantics - either play it under its rules for a strength calibration, or wrap it under CodinGame rules knowing it was not trained for them. Second: **uttt.ai's C++ NMCTS** (Apache-2.0, ~700 sims/s on GPU, weights on Drive) - probably the stronger engine but unbenchmarked; playing it against SaltZero would itself be a new result. Third: a **Legend-grade bitboard MCTS + solver** at 100 ms, rebuilt from the forum recipe (bitboards, 80-90 k rollouts, MCTS solver); no released Legend source, so this is a day's work, but it is the opponent that connects to the arena's Elo scale.
- **Code to borrow:** tacult's `utac` C++ engine (MIT, nanobind, vectorized MCTS) is the cleanest modern scaffold; uttt.ai's `utttcpp` (Apache-2.0) is proven at scale but idiosyncratic; alpha-zero-general (MIT) plus the unmerged UTTT PR is the simplest but pure-Python slow; OpenSpiel's game is clean but has the two-ply free-move quirk and no tiebreak, so a from-scratch 81-action bitboard environment matching `Referee.java` exactly is recommended. Apache-2.0 and MIT sources can be mixed freely; SaltZero's GPL-3 confines it to a separate opponent process, which is how it is meant to be used anyway.
